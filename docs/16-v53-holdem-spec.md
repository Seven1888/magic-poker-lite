**狀態：使用者已選方案 B；正式規格已定，`pooled-holdem` 整合與發布驗證進行中，尚未發布。**

本文件整合本次使用者確認的玩法及 2026-10-07 選定的方案 B。它是本次實作契約，不是上線公告；Git 推送、Pages 部署及最終驗收以完成後的正式紀錄為準。

使用者已要求完成所有調整後一併更新 Git，再建立新聊天室並提供全部連結；已明確選擇 **保留 99% 計分、個人雙池與 JP，允許 NPC 暗牌依結果目標切換**。正式模式為 `pooled-holdem`。先前的 `fixed-holdem` 固定牌自然勝負候選不是本次正式玩法，不能把其停用水池／JP 的設定帶入正式版。

## 1. 本次範圍與結果模型邊界

本次只處理 Magic Poker Lite。遊戲介面使用英文，機率工具與文件使用繁體中文。

| 項目 | 已確認的正式規格 |
| --- | --- |
| 德州流程 | 底牌 → Preflop → Flop 三張 → Turn 一張 → River 一張；各街進行下注 |
| 公共牌未發位置 | 開局顯示五個虛線空框，不先擺五張背牌 |
| 動作名稱 | 依合法狀態顯示 CHECK／CALL、BET／RAISE，保留 FOLD |
| 再加注 | 雙方可以多次合法再加注，沒有每街只加一次的限制 |
| 金額 | 半池、全池、ALL IN 三個選項；玩家自由選，NPC 依 50%／35%／15% 抽尺寸 |
| 對手 | 只有激進、不激進，連續下一手不重複 |
| 分類 | 只有強、不強；每街開始先判定，整街固定 |
| 公開機率 | 玩家行動前知道一般面對下注、免費 CHECK、不能再 RAISE 三種分支 |
| 買入 | 入場選擇數字是小盲；小盲 × 100 從 BALANCE 轉至 CHIPS |
| 補碼 | 同桌不額外買入、不自動補碼；每手對手起始碼量匹配玩家當時桌籌碼 |
| 保存 | 保存未完手、結果控制狀態、個人池及 RNG，重整繼續原桌，不重扣買入 |

### 已選方案 B：保留結果計分與水池

正式 `pooled-holdem` 結合新版德州下注、錢包與兩型對手，以及原本 99% 計分、個人雙池和 JP。玩家兩張底牌與公共牌序在開手布局完成後固定；NPC 可以依結果目標切換到另一組已預建的合法底牌。

因此這是有結果預算控制的德州風格遊戲，不能宣稱為全牌均勻隨機、雙方底牌永久固定的標準德州。行動機率也不是玩家勝率或 99% 回報保證。

- `conversionRate` 預設 0.99，仍是唯一結果計分係數；匹配底池全額派彩，不另扣 4% 或任何第二筆底池費。
- 個人付費池／特殊池按原 80%／20% 分配、CD 與 JP 規則繼續運作；資料跨手、跨桌及重整保存。
- 開手先預建固定玩家牌、公牌序，以及本手所需的 NPC `win`／`nonWin` 配對。操作時只選擇已建配對，不臨時搜尋新牌。
- 玩家實際付費後，仍由原結果公式決定是否從 `nonWin` 轉 `win`；已贏的非棄牌路徑繼承，不重新抽結果。
- 即使同一街 NPC 配對因結果目標而切換，已公開的本街強／不強分類與行為機率仍維持原快照；進入新街才依當時配對與已揭公共牌重判。
- 棄牌與攤牌仍使用實際 POT、退款及當前合法牌組結算；JP 另加，不把未派水池餘額當玩家資產。

### 技術契約：預建布局與精簡結果控制器

本次取消「開局實體展開全部無限加注合法分支」的要求，改用精簡結果控制器（compact controller）保存所選路徑的結果目標、池分支、資格、預建牌面與 RNG。

開手必須先完成本手需要的合法牌面布局，布局無解時不能先扣正式盲注或發布半成品。成功後，每次正式動作才依實際支付與當前池分支運算原公式；未選動作不入帳、不消耗正式結果票、不增加水池。

「預建」現在指牌面候選布局，**不表示所有未來動作的目標與結果票都已物化為節點樹**。這與舊 `prebuilt-pools` 的完整分支樹契約不同，文件、報表與 API 必須清楚區分。預覽不得推進正式 RNG、修改水池或換掉正式底牌。

### 計分、雙池與 JP 單位

| 項目 | 保留的公式／規則 |
| --- | --- |
| Root 結果 | 匹配盲注 × 0.99 ÷ 匹配底池；root 不增雙池、不使用付費池 |
| 原本輸且玩家實付 | 實付 × 0.99，加上 CD 為 0 時可用的付費池，再除以付費後可匹配底池；最多補到 100% |
| 原本贏且非棄牌 | 繼承結果，不重抽、不用付費池、不減 CD |
| 贏節點的有效付費 | 付費分數依 80%／20% 進付費池／特殊池；保存投入區間，結算按最終匹配額剪裁 |
| 不計入池 | 盲注、買入轉帳、未匹配退款及未選動作 |
| CD | 預設 0～0；原本輸且實際付費才依原規則減少，使用付費池後抽新 CD |
| JP 資格 | root 贏、特殊池足額，再依皇家／同花順／四條優先順序選最高可負擔獎，預設 20% 抽資格 |
| JP 派彩 | 玩家獲勝攤牌、牌型與資格相符且底牌有參與才扣池派獎；棄牌不扣不派；本手新增收入不能回頭資助開局資格 |
| 金額基準 | 池桶選擇及 JP 倍率都沿用大盲 BB，也就是舊版的 BET 單位 |

JP 為皇家同花順 `200 × BB`、同花順 `50 × BB`、四條 `20 × BB`。例如選小盲 10：BB 20、買入 1,000、皇家獎額 4,000。不要把這些倍率改乘 SB。

三個個人池桶改以 BB 範圍決定：低桶 `0 < BB ≤ 10`，中桶 `10 < BB ≤ 500`，高桶 `BB > 500`。所有原合法 BB 值仍落在原本的桶，三桶既有存量不搬動；新增 SB 選項加倍後產生的 BB 也可依範圍歸桶。例如 SB 2／BB 4 為低桶，SB 20／BB 40 為中桶，SB 2,000／BB 4,000 為高桶。

## 2. 盲注、錢包與桌籌碼

### 入場

| 計算 | 定義 |
| --- | --- |
| 小盲 SB | 入場選單選到的數字 |
| 大盲 BB | SB × 2 |
| 固定買入 | SB × 100，等於 50 BB |
| BALANCE | 桌外錢包 |
| CHIPS | 本桌可下注的實際籌碼 |

例如選擇 10：SB 10、BB 20、買入 1,000。若原 BALANCE 為 10,000，入場後 BALANCE 為 9,000，玩家 CHIPS 為 1,000。玩家若是小盲，扣盲後玩家 990、對手 980、POT 30。

按 FIGHT 才提交買入；選擇盲注本身不扣款。UI 先保存 BALANCE → CHIPS 的轉帳，再播放錢由錢包飛到玩家籌碼的動畫，之後開手、下盲注及發牌。動畫不新增扣款。

BALANCE 不足買入時禁止入場，提示選較小盲注。入場轉帳不是下注，不列入有效投入或 RTP 分母。

### 同桌期間

- 一切 CALL／BET／RAISE 從 CHIPS 扣除；不再次向 BALANCE 扣款。
- 各手盈虧累積到下一手，玩家 CHIPS 不重設為初始買入。
- 牌局中及手與手之間均不補碼；UI 同桌期間不開放 Reset demo chips。
- 同桌盲注固定；UI 要求離桌後才能選新盲注。
- 玩家還有正數桌籌碼就可以續手；不足完整盲注時以剩餘籌碼下短盲注。桌籌碼歸零就停止續手。
- 每手開始、扣盲注前，把新對手 CHIPS 設為玩家當時 CHIPS。這筆對手資產配置不是玩家收入、POT 或返還，手中不再匹配。
- UI 只允許在本手結束後離桌；剩餘玩家 CHIPS 一次轉回 BALANCE，不重複派彩。
- 離桌後重新入場是另一筆固定買入，不是對正在玩的牌局補碼。

## 3. 發牌與單挑行動順序

1. 入桌首手先以 50%／50% 抽玩家為 SB 或 BB。
2. 後續每手交換 SB／BB，採單挑德州輪替方式；不再每手重新抽盲位。
3. 各下盲注，雙方各發兩張底牌。Preflop 沒有公共牌，桌面保留五個虛線空框。
4. Preflop 由 SB 先行。SB 補平盲注後，BB 仍有 CHECK／RAISE 機會，不能因投入相等就跳街。
5. Flop 發三張、Turn 發一張、River 發一張；這三街均由 BB 先行、SB 後行。
6. 一方 FOLD 立即結束。雙方不再有可進行的下注時，補發剩餘公共牌並攤牌。
7. ALL IN 之後，畫面仍按 Flop／Turn／River 分段發出、翻開公共牌，未發位置繼續保持空框。

引擎開局先決定未公開的洗牌順序，不代表公共牌已經發到畫面。NPC 判定與公開參考勝率不讀未公開牌。

本次沒有新增燒牌動畫或燒牌步驟；如要納入實體發牌表演，應另列需求。

## 4. 動作、加注額與合法性

### 名稱與操作

| 狀態 | 按鈕 |
| --- | --- |
| 沒有待補差額 | CHECK |
| 有待補差額 | CALL，顯示本次實付 |
| 本街還沒有人下注 | BET |
| 本街已有下注或盲注 | RAISE |

點 BET／RAISE 先展開連接在該按鈕上方的尺寸選項，點選金額才提交。選項直接顯示本次要付的正確金額；實際全下額另標 ALL IN。相同合法金額合併為一個選項，不顯示重複金額。

### 半池／全池公式

- `P`：行動前底池，包含已投入的盲注與本街下注。
- `C`：尚需補的 CALL 差額。
- `s`：自己本街已投入。
- `x`：0.5 或 1。

```text
候選本次實付 amount = C + x × (P + C)
候選本街累計 to = s + amount
ALL IN 本次實付 = 自己剩餘 CHIPS
```

例如原底池 100，對方下注 50：此刻 `P=150、C=50`。半池要再付 150，全池要再付 250。UI 顯示的是這次付多少，不是本街總共下到多少。

### 合法化

- 最小開注為 BB。
- 最小完整加注增量為前一次完整 BET／RAISE 的增量。每街開始的基準為 BB。
- 半池或全池算出的金額低於最小合法額時，提高到最小合法額。
- 超過自己剩餘 CHIPS 時，改成自己的 ALL IN。
- CALL 不足時以自己全部剩餘 CHIPS 跟注。
- 不足最小完整加注的短 ALL IN 不替已行動者重新開放 RAISE。
- 對方已 ALL IN 時，不再提供額外 RAISE。
- 本作為兩人桌；超過對方實際匹配的投入結算時全額退回，不建立第三人的邊池。
- 不設每街 RAISE 次數上限，但受籌碼及加注權限制。
- 計算與帳務保存六位小數，顯示不應改變實際提交的金額。

### 引擎動作契約

`legalActions` 的動作包含 `id`、`type`、`amount`、`to`、`allIn`；進攻動作另有 `sizeKey`、`sizeKeys`、`fullRaise`、`raiseIncrement`。

例如 `raise:half`、`raise:pot`、`raise:allin` 是不同動作。若半池與全池都被提高或封頂到相同金額，`sizeKeys` 會同時記錄兩個來源。UI、預覽、NPC、重播與樹分析提交完整動作或明確 ID，不能只用 `raise` 丟失尺寸。

## 6. 強／不強判定

每街開始、該街牌面已在引擎揭示後，**在任何一方採取該街行動前**判定一次。只使用 NPC 自己兩張底牌、當時已公開公共牌，以及已完成階段的行動紀錄。

符合下表任一條即為強；全不符合即為不強。

| 階段 | 明確條件 |
| --- | --- |
| Preflop | 底牌對子；或兩張底牌點數都至少為 10；或兩張同花且包含 A |
| Flop／Turn／River | 目前最佳五張為對子以上，包含公共牌本身的對子 |
| Flop／Turn | 底牌加已揭公共牌中，某花色剛好有四張 |
| Flop／Turn | 四個連續點數，兩端各有一種點數能補成順子 |
| Flop／Turn 卡順詐唬 | 缺一張中間點數就能成順子；構成聽牌的至少一個點數只能由底牌提供；至少一張底牌大於公共牌最高點數 |
| River 未補成聽牌詐唬 | 目前只有高牌；NPC 在 Turn 曾 BET／RAISE；Turn 有涉及底牌、但到 River 沒補成的四花或雙頭順 |
| River 阻擋牌詐唬 | 目前只有高牌；公共牌恰好有三張同花；NPC 持有該花色 A；NPC 在 Turn 曾 BET／RAISE |

定義與邊界：

- 順子中的 A 只能是最小或最大，不能繞接。
- `2345` 與 `TJQK` 是雙頭順；`A234`、`JQKA` 不是。
- 涉及底牌的四花：四張同花中至少一張是 NPC 底牌。
- 涉及底牌的雙頭順：四個必要點數至少一個只能由 NPC 底牌提供。
- 公共牌自己有四花或雙頭順，在 Flop／Turn 仍算強；但 River 的「未補成聽牌詐唬」還須符合底牌參與條件。
- River 不能直接用尚未完成的聽牌判強，必須符合表中的詐唬條件。
- 不讀玩家暗牌、未來公牌、玩家下一步金額或本街的玩家下注。
- Turn 的底牌參與聽牌證據保存於該街快照，River 使用該已完成階段的資料。

玩家本街下注多少、再加注多少次，都不改此街分類。詐唬資格不因本街玩家開始下注而消失。`pooled-holdem` 因結果目標切換 NPC 配對時，也不重判當街；下一街翻新牌才使用當時實際選中的 NPC 配對重判。

因此「強」表示本街開頭已公布的策略分類，不保證切換配對後仍符合當下牌型。River 所需的 Turn 聽牌證據沿用 Turn 開頭保存的快照，不能被後來換牌改寫。

程式內部的 `bossStreetStrength`／`bossStreetStates` 可保存 band、reasons 與聽牌證據；它們不是遊戲 UI 的公開文案。

## 7. 行為機率

這些是已確認的遊戲設計百分比，不是真人玩家統計平均。強包含成牌、聽牌與詐唬，全部使用相同機率；不另加「持最大牌不棄牌」等隱藏特例。

### 一般面對下注，而且可以合法 RAISE

| 對手 | 分類 | FOLD | CALL | RAISE |
| --- | --- | ---: | ---: | ---: |
| 激進 | 強 | 5% | 25% | 70% |
| 不激進 | 強 | 5% | 65% | 30% |
| 激進 | 不強 | 45% | 55% | 0% |
| 不激進 | 不強 | 25% | 75% | 0% |

### 可以免費 CHECK，而且仍有合法進攻動作

FOLD＋CALL 合併為 CHECK，不因為無需補注而棄牌。

| 對手 | 分類 | CHECK | BET／RAISE |
| --- | --- | ---: | ---: |
| 激進 | 強 | 30% | 70% |
| 不激進 | 強 | 70% | 30% |
| 激進 | 不強 | 100% | 0% |
| 不激進 | 不強 | 100% | 0% |

若唯一合法選項就是 CHECK，使用 100% CHECK。

### 面對下注但不能 RAISE，例如對方 ALL IN

移除 RAISE，將原 FOLD／CALL 按比例正規化，不把 RAISE 全部轉為 CALL。

| 對手 | 分類 | FOLD | CALL |
| --- | --- | ---: | ---: |
| 激進 | 強 | 16.67% | 83.33% |
| 不激進 | 強 | 7.14% | 92.86% |
| 激進 | 不強 | 45% | 55% |
| 不激進 | 不強 | 25% | 75% |

顯示保留兩位小數，抽樣使用原始比值，例如激進強的 FOLD 為 `5 / (5 + 25)`。

### 尺寸與真正的兩段抽樣

| BET／RAISE 尺寸 | 條件機率 |
| --- | ---: |
| 0.5 倍底池 | 50% |
| 1 倍底池 | 35% |
| ALL IN | 15% |

每次輪到 NPC 都重新抽一次行為；只有抽中 BET／RAISE，才再抽一次尺寸。因此一般動作用一張 RNG 票，進攻動作用兩張。即使三個尺寸因籌碼限制合併成同額，仍保留尺寸抽票，使重播遵守同一契約。

供預覽與樹分析的各尺寸機率是行為機率乘上尺寸條件機率。若合法化後金額相同，來源尺寸的機率相加。15% 只表示直接抽中 ALL IN 選項；半池、全池因剩餘籌碼不足而封頂，也可能成為 ALL IN。

畫面抽籤條把同一 type 的多個尺寸合併成一個 BET／RAISE 區段；這是顯示合併，不改引擎實際尺寸選擇。動畫、UI 重繪、預覽與音效不抽新的行為票。

## 8. 玩家行動前的機率顯示

公開 API `getBossProbabilityScenarios(hand)` 回傳：

```js
{
  facing: {fold, call, raise},
  free: {check, raise},
  noRaise: {fold, call},
  sizes: {half: 0.5, pot: 0.35, allin: 0.15}
}
```

數值為 0～1 比例。回傳不含底牌、分類原因、牌型名稱或未來牌。

目前 UI 主條顯示對手名稱及一般面對下注的基表；點開資訊對話框可查看三種情境與尺寸機率。應清楚標示主條是一般面對下注基表，避免把免費 CHECK 情境誤讀為也有 FOLD 機率。

精確機率可讓玩家推知強／不強桶，這是已確認的資訊設計；**仍不直接顯示桶內究竟是成牌、聽牌或詐唬**。不能一方面顯示不同的精確機率，一方面宣稱強／不強本身完全無法推知。

對手暗牌在攤牌前以背面顯示，不把牌碼放入牌面 DOM。公開德州參考勝率仍只使用玩家底牌及已揭公共牌，對手分布參考工具也不讀 NPC 實際暗牌。

## 10. 機率工具與研究

遊戲與研究共用引擎、合法動作及 NPC 表，不另寫一套簡化出牌器。工具只列兩型及新的強／不強表，並顯示實際研究的 outcome model。

### 一般研究

- 無限外部研究錢包不等於桌籌碼無限。
- 每次研究入桌帶入 100 SB／50 BB；桌籌碼按每手輸贏累積，歸零才另開一次固定買入。
- 每手 NPC 匹配玩家當時桌籌碼，ALL IN 使用真實有限碼量。
- 研究重新入桌有獨立 `tableEntries`／`tableBuyIns` 記錄；買入不是下注，不加入 RTP 分子或分母。
- 研究可自動模擬離桌後再入場，遊戲不會在同桌自動補碼。
- 同一研究玩家的雙池、CD、資格序號、手序及對手序列跨手、跨研究入場延續；不同玩家不共用水池。
- 一般／退幣研究共用 `beginNewTable(session, {buyIn})` 重入；保留同一 session 的總手序、累計結果、池／CD及上一對手，從同一 RNG 序列抽一次新桌首盲，其後按新桌手序交替。首桌由 `createSession` 抽盲，不能多抽一次；未結束舊手或新桌尚未開手重複重入都拒絕。外部錢包轉帳仍由呼叫方處理。
- 連續研究按玩家聚類估算不確定性；樣本不足時不報可估區間。
- 報表保存各街、座位、動作與尺寸統計，來源尺寸合併資訊不遺失。

### 退幣研究

- 總資產定義為外部錢包＋桌籌碼；水池餘額不是玩家資產。
- 一次入桌從研究錢包扣 100 SB，桌籌碼歸零後，錢包足夠才模擬新入場。
- 達到目標資產即完成；桌籌碼歸零且錢包不足下一次買入則失敗。
- 不在正在進行的牌局補碼，不把買入與離桌視為獲利。
- 只有全部指定玩家及策略完成，才能發布完整退幣比例；中止時不得把部分完成樣本冒充全體結果。

### 行動研究與原完整樹的區分

半池、全池、ALL IN 及再加注均按動作 ID／金額保存。不得用 type-only Map 覆蓋相同 type 的多個尺寸，也不得用葉子數比例當勝率。

正式 `pooled-holdem` 使用預建布局及精簡結果控制器，不宣稱即時開局已列舉完整 NL 行動樹。舊版完整樹 API 如保留為歷史研究，必須標明模式與限制；不得把單一抽樣控制路徑報成全部可能結果。普通統計與退幣研究用正式引擎逐手實際抽樣。
