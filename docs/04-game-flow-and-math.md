## 1. 現行規則與參數

雙方各兩張底牌，共用五張公共牌，從自己的七張可用牌取最佳五張。沒有鬼牌、換牌、魔法或結果池。數學共用 `engine.mjs`、`poker.mjs`、`jackpot.mjs`；規則識別為 `heads-up-two-blinds-v1`。比對報表還須核對重抽模式、參數和統計模式，不能只看規則識別。

| 項目 | 預設／規則 | 意義 |
| --- | --- | --- |
| 初始資產 | 10,000 | 本頁原型資產；正常下一手不重設 |
| 基礎大盲／BET | 10 | 工具基礎設定；遊戲入口預選 BET 1 並同比縮放 |
| 小盲 | 0.5 × 大盲 | 固定推導，舊匯入值也重算 |
| 四街固定增量 | 10／20／40／40 | 翻牌前／翻牌／轉牌／河牌 |
| 每街加注上限 | 1 次 | 翻牌前大盲已構成本街下注 |
| 底池返還係數 | 0.96 | 分得的匹配底池乘此係數，不是總 RTP 保證 |
| JP | 皇家 200／同花順 50／四條 20 倍 BET | 只領最高符合的一獎 |
| 玩家重抽 | 未成對時 50%，最多 50 次 | 接受最後候選，不看最終輸贏 |
| BOSS 重抽 | 未成對時 25%，最多 50 次 | 雙方分別設定 |

金額內部取六位小數，UI 保留至多六位小數；模型設定 BET 0.03 的小盲為 0.015。遊戲 BET 選單使用下列固定 15 級。最低入桌資產預設 20 BB：基礎 `minBuyIn=200`、`maxBuyIn=10000`、`buyIn=10000`。保持原 BET 時，同桌低於入場門檻仍可繼續短籌碼牌局；任一方低於 0.01 才不能開下一手。改 BET 須雙方資產都達新門檻。

## 2. 入桌、合法動作與演出

入口只選 BET，不扣款或抽牌。FIGHT 建立 session，以一次 50/50 抽樣決定首手盲位，其後逐手交換。提示只列開局誰先／誰後，以及 YOU／BOSS 各自初始投入；BET 1 時是 0.5／1，不是各 10,000 的持有資產。小盲翻牌前先行動；翻牌、轉牌及河牌由大盲先行動。

入口及局間 BET 使用 Hands Up 正式 `simulation-engine.js` 的 `FIXED_STAKES`：**1、2、5、10、20、50、100、200、500、800、1,000、1,200、1,500、1,800、2,000**，共 15 級，入口預選 1。＋／−移至相鄰級距，不採固定加法 step；工具的基礎 bigBlind 不會改變此選單。

每手結算及派彩演出完成後，左側較小 BET 開調整小窗，右側 NEXT HAND 開下一手。＋／−只調草稿；CONFIRM BET 只保存下一手設定，關閉取消草稿，不扣款或抽 RNG。`nextHandBetConfig(session,bet)` 按目前 `bet/config.bigBlind` 比例縮放兩盲、四街注額及資產門檻；變更時雙方實際資產須達 `minBuyIn/bigBlind × 新 BET`（預設 20 BB）。原 BET 不變保留短籌碼續手；NEXT HAND 才依新設定扣盲發牌。

局間確認不重建 session：保留原資產、`buyIn` 損益基準、歷史、RNG、局號、盲位輪替與 BOSS 排除上一型的序列。只更新 `session.config`，本手已結算 `hand.config`、派彩和 JP 結果不變；新 BET 對應的 JP 金額由下一手使用。

| 局面 | 合法引擎動作 |
| --- | --- |
| 尚欠跟注且本街可加注 | fold／call／raise，以雙方可匹配資產為限 |
| 尚欠跟注，已加注一次或對手全下 | fold／call |
| 不欠跟注、本街尚無下注 | check／bet |
| 翻牌前小盲已跟至大盲 | 大盲仍可 check／raise |

雙方畫面名稱統一 FOLD／CALL／RAISE：`check` 與 `call` 顯示 CALL，`bet` 與 `raise` 顯示 RAISE。引擎真實 type 不變；這不是標準德州術語合併。付費按鈕顯示本次新增支付 `amount`，不是加注至總額 `to`；免費 CALL 與 FOLD 不列金額。

玩家付費後，籌碼先抵達 POT，才將該按鈕上方的獨立機率 preview 飛往中央，再演對手決策。每塊 preview 左側只標一次 **BOSS**，右側列原機率，兩側異色且合成同一塊。免費 CALL 可略過投入；FOLD、換街或 BOSS 先手沒有有效來源時，不借用上次按鈕。只抽一次結果、只執行一次行動；動畫不決定結果或改 RNG。常駐底板位於公共牌上方，只顯示當前 DEALING／YOUR TURN／BOSS TURN，不另設 POT 階段。

v38 起，同手同街確有 BOSS 直接回應時，即使只有一個正機率動作也顯示 **BOSS CALL 100%／RAISE 100%／FOLD 100%**；名稱沿用上方映射。混合分布的按鈕預覽仍只列原始 FOLD／RAISE，不補列 CALL、不重新正規化。直接換街、結束牌局或沒有同街回應的候選動作仍不列預覽，不借未公開下一街或過期分布填空。這只修正唯讀預覽，中央抽選與必然動作演出維持既有行為。

BOSS 名稱與副標不顯示。角色近景與桌前底牌上移，保留與公共牌的間距及行動底板空間；角色不持牌，各型造型維持。BOSS 牌型文字由 14 放大至 17.5 舞台 px（＋25%），底板由 170×25 放大至 214×30，top 保持 326，仍依已公開資訊顯示。畫面依序為角色牌→行動資訊→公共牌→POT→玩家手牌，玩家手牌上方直接是 POT。雙方籌碼維持桌布上的放大實體堆。POT 與金額後方籌碼居中；TOTAL WIN 在 POT 區演出，使用底池返還＋JP、排除退款。來源堆保留至真正派出抵達，不能為排版提前清空或重新派彩。

公共牌依 FLOP 3 張、TURN 1 張、RIVER 1 張有序翻開；FLOP 三張交錯啟動，不能提前公開牌面。牌面在側邊換圖，牌型、亮框及可見張數等 `onVisible` 正面展開完成才更新；玩家兩張底牌都可見後才顯示牌型，BOSS 依真正揭開的底牌逐張更新，換手清空舊牌型。BOSS 棄牌保持背面。玩家／已公開 BOSS 的最佳五張（含踢腳牌）使用實色 4px 金色 #ffe019／藍色 #259dff 框與深色分隔，共用牌金內藍外，完整揭牌後才調暗未入選牌。

NEXT HAND 由原本 `startHand` 選型，畫面同步切換新 BOSS neutral；入口預載四型 neutral，未完成圖片解碼時用角色區轉場，發牌前最多等 4 秒，失敗／超時使用無型名替身。晚到圖片不能覆蓋已切換的角色，預載與轉場不選型、不追加 RNG。表情只在結果可公開後切換。BOSS 實際執行任一動作時，角色前方同步浮出 FOLD／CALL／RAISE；RAISE 用紅字。付費動作與對手籌碼出發同步，免費 CALL 與 FOLD 也顯示。完整呈現契約見 [美術與 POT](05-art-and-pot.md)。

## 3. 牌庫與起手重抽

### 3.1 未成對重抽

參考 Boss Duel 的「弱牌條件＋逐次重抽率＋上限＋接受最後候選」結構，適配兩張底牌時，弱牌條件明確為 **未成對**。不是直接套用 Boss Duel 六張牌的牌力判斷。

1. 先保留雙方指定底牌，從可用池移除；指定牌彼此不可重複。
2. 小盲先取候選兩張，再輪另一方；候選內不重複。
3. 已成對即停。未成對且未達上限時，依該方重抽率決定是否再抽。
4. 重抽從同一可用池再取兩張；落選牌留在池中，可能再被抽到。新候選即使更弱也採用，不與舊候選取最大值。
5. 成對、停止抽樣或達上限後，才移除最後採用兩張。雙方最後底牌不重複。
6. 洗剩餘牌，按固定牌序逐街發公共牌。

最多 50 次是初抽之後最多 50 次重抽，共最多 51 組候選，不是固定抽滿。指定底牌跳過該座位抽樣／重抽，`attempts=0`。不看公共牌、JP、最終勝負或資產損益。

未保留牌且先處理該座位時，單次成對率 `a=78/1326=1/17`。重抽率 r、上限 K、`q=(1-a)r`，採用成對率可檢查為：

```text
P(最後成對) = a × (1 + q + ... + q^K)
            = a × (1 - q^(K+1)) / (1-q)
```

另一方已接受底牌或指定牌會改變可用池，須依實際牌池計算。此式是重抽的局部機率，成對率不等於贏局率。

### 3.2 舊設定與稽核

`deal.player/npc` 各含 `rerollMode`、`rerollChance`、`maxRerolls`、`manual`。新預設為 `unpaired`。明確 `legacy-score`，或舊設定沒有 mode 但有 `targetScore`，維持分數門檻，不無聲改成新模式。舊模式未填值預設為機率 0.75、最多 2 次、門檻 0.48；明確保存的值仍保留。

`dealAudit[seat]` 記錄 manual、模式、initialClass／finalClass、initialScore／finalScore、attempts、rerolls、stopReason。停止原因可為 manual、pair、score-threshold、limit、probability。工具彙總雙方稽核。

舊門檻與翻牌前行動牌力採 `holeScore`，不是精確勝率。H／L 為高低點數，A=14：

```text
成對：min(1, 0.57 + (H-2)/12 × 0.43)
未成對：clamp((H-2)/12 × 0.44 + (L-2)/12 × 0.20
               + 同花加分 + 間距加分, 0.02, 0.94)
同花加分：同花 0.12，否則 0
間距加分：H-L 為 1／2／3 時，分別 0.12／0.07／0.03，否則 0
```

## 4. BOSS 行為機率與玩家策略

### 4.1 均等輪替與固定機率

首手四種各 25%；之後排除上一手類型，其餘三種各 1/3。長期邊際機率相同，不代表有限牌局四型次數必相等。只在 startHand 選取一次，動畫、預覽及全樹展開不重選。

`config.boss={mode:'rotate',profileId:'caller'}` 為新預設。mode 可為 rotate（輪替）、fixed（固定研究、允許重複）或 legacy（舊權重模型）。固定研究由 profileId 指定 caller／maniac／sniper／trapper。舊設定未含 boss 時採新輪替；要重現舊數據必須明示 legacy，不能假設舊種子在新模型仍發出同一副牌。

每個 BOSS 依「街道＋當下牌力」讀固定表；沒有再加隱藏性格亂數或強度係數。動作本身仍依表抽樣，因此性格是傾向。牌力只讀自己的底牌與已揭公牌，不讀玩家暗牌、未來公牌或結果。

| 牌力級別 | 明確條件 |
| --- | --- |
| 弱起手 | 翻牌前兩張起手分數低於 0.42。 |
| 可玩起手 | 翻牌前起手分數介於 0.42（含）至 0.66。 |
| 強起手 | 翻牌前起手分數至少 0.66；分數是策略分類，不是勝率。 |
| 高牌 | 尚未成對，也沒有四張同花或四張順子聽牌。 |
| 一對 | 最佳五張恰好一對，包含公牌形成的一對；沒有聽牌。 |
| 聽牌 | 翻牌或轉牌時，最多一對，且可見牌有四張同花或五張順子窗口中的四個不同點數。 |
| 強成牌 | 目前最佳五張為兩對或以上，優先於聽牌分類。 |

翻牌前分數公式見第 3 節。翻牌後優先順序為強成牌 → 聽牌 → 一對 → 高牌；河牌沒有聽牌類別。兩對包含公牌形成的牌型，是策略分級，不保證領先玩家。

表格原始三欄總和 100%。先剔除不合法動作，再按剩餘欄正規化。免費時不選 FOLD，CALL 映射 check、RAISE 映射 bet／raise；例如狂攻弱起手的 8／22／70，免費時為 CALL 22/92=23.913%、RAISE 70/92=76.087%。已達加注上限時不再抽 RAISE；如果只剩單一合法有權重動作即為 100%。實際按鈕預覽與中央抽選都使用這個最終分布。

每街最多加注一次仍不變，狂攻只在合法次數內更常加注；設局型強牌前街偏過牌／跟注，後街提高攻擊，並不是每次必定反加。

### 4.6 模擬玩家策略與舊模型

先求合法動作，只對合法項目分配權重。對手只讀自己的底牌、已揭公共牌與下注狀態；不讀玩家暗牌或未來公共牌。預覽在 clone 上執行，不消耗真實 RNG。

令牌力 s、待補金額 owed、成本比 `q=owed/max(.01,POT+owed)`；S 為 strengthInfluence（預設 1），P 為 priceInfluence（預設 .6）。基礎權重 `bFold=.2,bCall=.6,bRaise=.2,bCheck=.65,bBet=.35`，不是最終百分比：

```text
wFold  = bFold  × exp(S × (0.5-s) × 3 + P × (q-0.2) × 2)
wCall  = bCall  × exp(S × (s-0.5) × 0.6)
wRaise = bRaise × exp(S × (s-0.5) × 2.5 - P × q)
wBet   = bBet   × exp(S × (s-0.5) × 2.5 - P × q)
wCheck = bCheck × exp(-S × (s-0.5))
P(action) = wAction / 所有合法動作權重總和
```

翻牌前 s=`holeScore`；翻牌後從高牌到同花順的基準為 `[.18,.40,.57,.67,.76,.82,.89,.96,.995]`，加 `(主要比較點數-8)×.008`，限制於 .03–.999。合法權重全為零時回退至過牌／跟注，不產生 NaN。

| 玩家策略 | 內部鍵 | 行為 |
| --- | --- | --- |
| 平衡 | balanced | 原始公式，使用自己可知的牌 |
| 始終跟注 | call | 合法 call 優先，其次 check；選定項目機率 1 |
| 積極 | aggressive | fold 權重 ×.15；bet／raise ×3.5；其餘 ×1 |
| 保守 | tight | fold ×3；bet／raise 在 s>.72 時 ×1.5，否則 ×.25 |

**balanced、aggressive、tight 的基底讀取 `config.npc`；call 是例外。四種新 BOSS 只讀固定表，不受這些玩家策略權重影響。** 只有 `boss.mode=legacy` 的 BOSS 才使用上列 balanced 公式。玩家策略不是最優解，也不看未來牌。

`sampleDistribution` 取一次 u∈[0,1)，按累積機率選動作。中央區寬忠於原分布，游標使用同一次 `selected.roll`，不重抽、取區段中心或重新正規化剩餘選項。遊戲旁的參考勝率另用可見牌與獨立 RNG，按未知對手均勻持牌算 `(勝+平/2)/樣本數`，未校正重抽或下注範圍；不是行動機率、樹勝率或 RTP。

## 5. JP、退款、底池與守恆

### 5.1 JP 牌型與倍數

| 最佳五張牌型 | 倍數 | BET 1 獎金 | BET 10 獎金 |
| --- | --- | --- | --- |
| 皇家同花順 | 200 × BET | 200 | 2,000 |
| 同花順（非皇家） | 50 × BET | 50 | 500 |
| 四條 | 20 × BET | 20 | 200 |

玩家正常攤牌才判定（含匹配全下補完牌），只領最高符合一獎；可用零／一／兩張底牌，不必贏底池。任一方棄牌均不觸發攤牌 JP；BOSS 不領 JP。JP 由額外資金提供、不另收投注、不扣底池費用。這是本作接法，不冒稱舊作全部條件相同。

### 5.2 單手帳務

雙方原始投入 Cplayer／Cnpc，每方有效投入 `m=min(Cplayer,Cnpc)`，匹配底池 `G=2m`，返還係數 t=.96：

```text
refund_i      = C_i - m
gross_i       = 贏池 G；平手 G/2；輸池 0
netReturn_i   = round6(gross_i × t)
fee_i         = gross_i - netReturn_i
totalReturn_i = netReturn_i + jackpotAward_i
baseProfit_i  = netReturn_i - m
profit_i      = totalReturn_i - m
stackAfter_i  = stackBefore_i - C_i + refund_i + totalReturn_i
```

`TOTAL BET=totalContribution`，`TOTAL WIN=player.totalReturn`；後者不是淨利，也不含退款。明細分開投入、退款、有效投入、費用、底池返還、JP、總返還及淨損益。

```text
玩家結束資產 + BOSS 結束資產 + 全手費用
= 玩家起始資產 + BOSS 起始資產 + 玩家 JP
```

本式檢查的是 **對手刷新前** 的結算快照。遊戲每手演出結束後另呼叫 `syncOpponentBankroll`，令 BOSS 下手資產匹配玩家餘額，`adjustment=after-before` 可正、負、零；玩家與本手 result 不改，同手重入不重做。它是獨立 DEMO 調整，不屬費用、退款、JP、派彩或 RTP。

### 5.3 RTP

```text
baseRtp  = ΣnetReturn / Σm
totalRtp = Σ(netReturn + JP) / Σm
profit   = ΣtotalReturn - Σm
```

退款不進分子或分母；不用每手 RTP 平均代替總和之比。完全對稱的牌力、策略、位置與資產才有底池對稱參考 96%；目前 50%／25% 重抽已不對稱，不能直接套此結論。JP、策略及指定牌會改變結果；本作未校準成固定 96% 或 99% 總 RTP。

## 6. 可逐筆核對的例子

以下固定 BET 10、SB 5／BB 10、雙方起始 1,000、t=.96；是受控帳務例，不是現行預設 10,000 的自然命中統計。

| 情況 | 原始投入 玩家／BOSS | 玩家退款 | 有效投入 | 玩家底池返還 | JP | 淨利 | 玩家結束 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 玩家 SB 立即棄牌 | 5／10 | 0 | 5 | 0 | 0 | -5 | 995 |
| 玩家加至 20，BOSS 棄牌 | 20／10 | 10 | 10 | 19.2 | 0 | 9.2 | 1,009.2 |
| 投入相同、攤牌平手無 JP | 10／10 | 0 | 10 | 9.6 | 0 | -.4 | 999.6 |
| 公共牌皇家同花順 | 10／10 | 0 | 10 | 9.6 | 2,000 | 1,999.6 | 2,999.6 |
| 玩家四條但仍輸池 | 10／10 | 0 | 10 | 0 | 200 | 190 | 1,190 |

第一例先退 BOSS 未匹配 5，再由匹配底池 10 收費 .4、返還 BOSS 9.6，BOSS 刷新前資產 1,004.6。第二例先退玩家 10，再派 19.2，TOTAL WIN 是 19.2，不能顯示 29.2 或淨利 9.2。公共皇家例平分底池、全手費用 .8，BOSS 不領 JP。四條輸池例說明贏池與正淨利不同。

## 7. 單副牌的完整行動樹

`buildActionTree` 先依共用引擎發牌，鎖定該手 BOSS、雙方底牌與剩餘牌序，再展開四街 **全部合法動作**。節點含當下 actor、street、已揭 board、資產、POT、投入、edges、到達機率與條件期望；終端保留引擎 result。

預設設定、seed 123、玩家小盲為 **1,312 節點＝562 決策＋750 終端**，最大深度 15。短籌碼／增量等會改變樹大小，不是任何設定都固定 1,312。始終跟注策略仍保留機率為零的合法棄牌／加注分支，其加權到達機率為零。

```text
P(根)=1
P(子節點)=P(父節點) × P(該動作 | 當下狀態)
E(節點)=Σ合法動作 [ P(動作 | 狀態) × E(子節點) ]
贏池機率=Σ贏池終端 P(終端)
返還期望=Σ終端 [ P(終端) × totalReturn ]
Σ全部終端 P(終端)=1
```

不能用贏的葉子數／總葉子數當勝率。`expected` 是到達該節點後、依策略繼續的條件期望；要計對全局貢獻才乘 `reachProbability`。`rootOptions[].expected` 比較首步後的條件期望，是已固定牌序的離線分析，不是遊戲內看穿未來的最優建議。

完整的是 **一副固定牌序的動作樹**，沒有枚舉全部 52 張牌的發牌排列。匯出包含雙方底牌及 `boardRunout`，僅供離線分析；節點 board 與策略仍限制於該步已知資訊。展開透過 clone／applyAction，不抽行動 RNG；`rngStateAfterTraversal` 必須等於發牌後狀態。超過 stateLimit 直接報錯，不交付假完整的截斷樹。

## 8. 抽樣牌序 × 完整分支積分

`simulateTreeStudy` 由主種子派生一組牌序種子，按玩家／BOSS 小盲交替；每副牌建立完整樹，積分所有合法路徑，再跨牌序平均。輪替設定在此把每副樣本視為獨立新牌桌，四型各 1/4，因此相鄰樣本可能相同；遊戲及多玩家序列研究才是同桌不連續重複。此抽樣差異記於 `meta.bossSampling`，不能把獨立樹樣本當作連續遭遇序列。同主種子、樣本數可以讓不同玩家策略共享相同牌序排程。

每副牌內不再抽單一路徑，但牌序本身仍是抽樣；不是全部牌組精確枚舉。**一個樣本是一副牌的一棵完整樹，750 個葉子不是 750 個獨立樣本。**

| 指標 | 定義 |
| --- | --- |
| 全局贏池率 | 平均 winProbability，包含 BOSS 棄牌 |
| 攤牌且贏聯合機率 | 平均 showdownWinProbability |
| 攤牌條件勝率 | Σ攤牌且贏質量／Σ攤牌質量 |
| 正淨利率 | profit>0 的終端質量平均，含 JP |
| 街／座位行為 | 該動作加權到達次數／該座位該街全部決策加權到達次數 |
| JP 分級機率 | 該獎級終端質量／牌序樣本數 |
| RTP | 返還條件期望總和／有效投入條件期望總和 |

同一方同街可行動多次，visitsPerDeal 可以大於一次，不能當「曾使用該動作的手數比例」。報表另列節點總量、終端、零機率邊、最大帳務守恆誤差與終端質量誤差。

第 d 副完整樹的有效投入、返還期望為 Xd／Yd，N 副牌、`r=ΣYd/ΣXd`：

```text
SE(r) = sqrt( N/(N-1) × Σ(Yd-r×Xd)^2 ) / ΣXd
95% CI = r ± 1.96 × SE(r)
```

贏池率以 N 個樹 winProbability 的樣本變異數算 `SE=sqrt(s²/N)`，區間裁至 0–1。單副牌或零有效投入不提供有效比率區間。這是常態近似；稀有 JP 零命中不代表機率為零，小樣本不能證明尾部收斂。

## 9. 三種玩家統計模式與分母

`simulateStudy` 逐手、逐行動抽樣，沿抽中路徑完成牌局；與全樹共用引擎。每位玩家由主種子與索引固定派生獨立亂數流，增加玩家數不改變前面玩家。

| 模式 | 資產／盲位 | 停止條件 | RTP CI 的樣本單位 |
| --- | --- | --- | --- |
| independent 獨立牌局 | 每手雙方重設 buyIn；每位首手玩家小盲後輪替 | 每位完成 entries 手 | 四型輪替：一位玩家整段；固定／舊模型：一手 |
| continuous 連續遊玩 | 保留玩家資產；首次隨機盲位後輪替，每手後匹配 BOSS | 完成 entries 或資產不足 .01 | 一位玩家整段投入／返還 |
| cashout 資產達標 | 同 continuous | 達 targetAsset、不足 .01 或安全上限 | 一位玩家整段投入／返還 |

cashout 達安全手數上限仍未達標／不足者記 censored（截尾），不算達標或失敗；開局已達標可有零手數。低於最低入桌門檻不代表同桌破產。連續模式最後一手也記 BOSS 刷新，`npcRefreshAdded`／`Removed`／`Adjustment` 另列，不算玩家回收。

獨立模式 `playerResults[].end` 只是最後一手資產，`endMeaning='last-independent-hand'`，不是累積餘額。普通策略比較即使主種子相同，行動消耗 RNG 不同，後續牌序未必相同；要固定同牌比較，使用第 8 節。

| 報表項目 | 分母／單位 |
| --- | --- |
| 玩家贏／輸／平率 | 各手數／已完成 hands |
| 攤牌條件勝率 | showdownWins／showdowns，平手不算贏 |
| 正淨利率 | netWinningHands／hands，profit 含 JP |
| JP 全局／攤牌命中率 | jackpotHits／hands；jackpotHits／showdowns |
| 街道到達率 | streetReach[street].hands／總 hands |
| 動作次數 | actionStats.count，同手可重複 |
| 使用動作的勝率 | handWins／hands；同街／座位／動作每手去重 |
| 單手返還倍數 | totalReturn／matchedWager，不含退款 |
| 達標／不足／截尾率 | 對應玩家數／模擬玩家數 |

動作表即使列 BOSS 動作，勝負欄仍指玩家。切片用於局部／累積帳務，不是連續模式的獨立樣本。RTP CI 用第 8 節比率公式：固定／舊 BOSS 的獨立模式代入每手 X／Y；四型輪替即使重設資產，也有不連續同型的跨手相關，因此按玩家聚類。連續及達標同樣代入每位玩家整段 X／Y。少於兩個樣本單位不報區間；一位連續玩家跑很多手仍沒有玩家聚類 CI。`methodMeta.ciUnit`／`ciSamples` 保留實際口徑。

## 10. 工具操作與 API

工具包含模擬設定、大小盲與四街、雙方起手、四種 BOSS 的完整逐街表、玩家策略權重、JP 牌型倍數、完整行動樹。普通統計、單樹、抽樣牌序完整樹統計分開執行／匯出。保存結果須帶設定、種子、模式、策略、樣本及 CI 單位，不只擷取百分比。

```js
buildActionTree(config, {
  seed:123, firstSmallBlind:'player', policy:'balanced', stateLimit:100000
});
simulateTreeStudy(config, {
  deals:100, seed:20261005, policy:'balanced', onProgress
});
simulateStudy(config, {
  players:10, entries:1000, seed:20261005, policy:'balanced',
  mode:'independent', sliceSize:250, targetAsset:20000,
  maxHandsPerPlayer:10000, onProgress
});
```

| 輸出 | 主要 schema |
| --- | --- |
| action-tree | version=1、mode=fixed-deal-full-action-tree、complete、meta、config、seed、firstSmallBlind、policy、cards、nodes、summary、rootOptions |
| node | id／parentId／depth／path／actor／street／reachProbability／board／stacks／pot／contributions／streetBets／currentBet／raises／pending／terminal／edges／expected；終端另含 result |
| edge | type／amount／to／allIn／probability／childId |
| expected | 勝平負機率、原始／有效投入、退款、gross／base／JP／total 返還、baseProfit／profit、playerFee／systemFee、雙方結束資產 |
| tree-study | kind=tree-study、deals／dealSeeds／blindCounts、weighted／totals、RTP／CI、tierProbabilities、byStreet、節點及誤差統計、meta |
| simulateStudy | studyVersion=1、mode、players／entries、playerResults／playerSummary、actionStats、streetReach、dealAudit、returnDistribution、batches、methodMeta、帳務／RTP／CI／BOSS 刷新 |

Worker 請求為 `{type:'run',config,policies:[...],...settings}`、`{type:'tree',config,...settings}`、`{type:'treeStudy',config,...settings}`；分別回傳 progress／partial／result、treeResult、treeProgress／treeStudyResult。錯誤為 `{type:'error',message}`。停止由 UI 終止 Worker，未完成策略不能冒充完整報表。完整逐欄契約見 [API-CONTRACT.md](../API-CONTRACT.md)。

儲存供遊戲使用只保存設定，重新入桌才套用，不重寫進行中的牌局。底牌輸入留空或各兩張，不能重複。原型沒有後端持久錢包；重新載入會初始化當頁狀態，正常離桌／再入桌保留實際餘額。

## 11. 與 Hands Up、Boss Duel 的界線

對照來源是同層最新版 `Hands Up/simulation-engine.js`、`Hands Up/app.js` 及工具，不是 `Hands Up/舊Hands Up/`。最新版具有先抽 win／lose 目標、再要求牌面符合的流程，也有依真實牌面導出的特定分支；其 0.99 是該作 RTP 目標，不能叫作玩家 99% 勝率。

本作採用完整分支、玩家行為、資產模式、切片、JP、匯出與交接架構。發牌與結算保持真實德州牌力，四種對手按表行動；不預先抽輸贏或用目標配牌拉高勝率。玩家勝率應從實際模型、所選策略與對手分組報表查證。

v37 另沿用該正式檔案的固定 BET 級距，唯讀核對 `FIXED_STAKES`（第 55 行），沒有移入 Hands Up 的發牌、預算或 RTP 規則。

Boss Duel 的起手重抽已適配為兩張未成對、玩家 50%／BOSS 25%、上限 50 次；不以最終輸贏重抽。原三款保持唯讀，本作不直接依賴它們的檔案路徑。
