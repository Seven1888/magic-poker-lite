## 最新 v29：完整流程的呈現整合（2026-10-04，本地完整流程驗證通過）

入口第 2 頁使用完整 20% FOLD／50% CALL／30% RAISE 連續比例範例；動作用途僅文字與細色底線，不用可點按矩形外觀混淆資訊與按鈕。範例須標 EXAMPLE。

中央顯示完整分布的連續真比例長條，區寬使用原始機率，marker 落點使用真實 `selected.roll`，不能改成選中區塊中央、正規化剩餘選項或追加抽樣。機率至少 10% 的區段將名稱與百分比留在格內；只有低於 10% 的小區段使用對應邊緣 caption，不把大區文字一併移出，真實區寬維持不變。玩家按鈕維持 FOLD／CALL／RAISE，badge 只列 FOLD／RAISE，材質恢復原寶石；實際花費規則維持。底牌 gap 10px、±2°，雙方恢復原 legacy 牌型美術，NPC 牌型直接位於底牌下；強化金／紅最佳五張與共用雙色，不改暗牌可見時機。

牌桌單顆 coin 抽出玩家 SB／BB 後飛往座位，盲注按 SB→BB 串行入 POT，沿用既有盲位結果及帳務。TOTAL WIN 於牌桌精確跑分並取代自動結算 modal；手動明細保留。取玩家 `p.totalReturn = p.netReturn + p.jackpotAward`，排除 `p.refund`，不能拿 profit 代替或因動畫再派彩。POT 示意籌碼置左、精確值置右，依顯示字數縮字並保留最多六位小數，不截斷或改成近似值。TOTAL WIN 在 POT 實體籌碼仍在時避開籌碼，真正派出後才回到中央；不能為排版提前清空可視籌碼或更動派彩。所有變更只投影既有引擎結果，RNG、賠率與金流不變。

本地完整流程驗證通過：`npm test` 165／165，Chrome／WebKit 自然四街、抽盲與 SB→BB 串行投入、棄牌退款、TOTAL WIN 1.92 與手動明細一致、NEXT HAND、連點只執行一次，以及靜音期間 34 次動畫新增 0 個聲源皆通過。使用者要求台灣時間 2026-10-04 06:00 前完成全流程 QA 與優化後才提交／推送，不提交半成品。驗證證據與發布狀態另見 [手機與部署紀錄](../../../docs/06-mobile-and-deployment.md)；本地通過不代表已提交或上線。歷史 v28 驗證不能代替本輪。

## 最新 v27：固定 FOLD／CALL／RAISE 與本次花費（2026-10-03）

依使用者最新指示，玩家按鈕名稱固定左 FOLD／中 CALL／右 RAISE：底層 `check`／`call` 都映射成 CALL，`bet`／`raise` 都映射成 RAISE。這是本作簡化介面名稱，不是標準德州術語定義；引擎 `type` 與 NPC 真實機率種類仍保留 `check`／`call`／`bet`／`raise`。付費 CALL／RAISE 顯示籌碼小圖＋實際新增支付金額，取合法動作 `amount`，不能用 `to` 或重複加上盲注。免費過牌的 CALL 不顯示籌碼／0；FOLD 只顯示名稱，沒有籌碼／金額。保留 NPC 回應機率與最多六位小數格式。本段覆蓋 v25／v26 的按鈕無金額規格，其他雙盲、RNG、帳務、單擊鎖與演出規則維持；更新教學圖時使用本版實際畫面，不將舊圖當作新驗證。

v27 另要求：有效主按鈕回應欄中的 FOLD／RAISE 選項，從按鈕頂端飛到中央並放大，抵達後才演出原抽選。來源須同手同街，不沿用必然、跨街或 NPC 先手前的舊按鈕；只保留原始顯示機率，不補列 CALL／CHECK／BET、不重新正規化，結果只抽一次。牌庫維持右上位置與計數，外觀改成躺桌斜視角及疊牌厚度，與直立手牌區分。

入池飛行末幀不能淡掉：每路抵達時先更新 POT 實體堆及該筆金額，再移除飛行替身，不能把另一條尚未到達的盲注提前入池。`onPhase` 的 `arrival` 每次落地通知一次，舊 generation 取消不通知；reduced motion 有語意落地通知，保留 watchdog。退款／派彩端點不變，飛行／落地音效服從 mute。NPC 棄牌收攏滑出但保持蓋牌。玩家金框、已揭 NPC 紅框及共用雙色框加強，牌間距放寬，公共牌略懸浮及增加側厚；不改判定與暗牌可見性。

入口改為較小的三段布局：特色介紹／獨立 BET 區／獨立 FIGHT 按鈕，預設 BET 1、只留＋／－，移除六個快捷值按鈕。選值不扣款，FIGHT 才建立 session 並抽盲。這些為 v27 規格，完成與驗證狀態見最新 QA，不用舊圖或舊測試宣稱整批完成。

## 沿用的核心實作方向

- 使用者已要求製作。手機直版、低桌面第一人稱、固定同一位手繪卡通怪獸電腦對手；角色以使用者最新附圖要求為準，不再採女性定稿。原牌面獲授權複製到新工作區；舊專案不變動。
- 兩張底牌＋五張公共牌，四街下注，保留雙方餘額、每街最多一次加注。入場先抽一次 50/50 大小盲再發牌，之後逐手輪替。UI 演出已決定的結果，不額外抽籤。合法動作區分過牌／下注與跟注／加注。
- 入桌只選 BET＝大盲；最低資產依原設定的 minBuyIn／bigBlind 比例計算，預設 20 BB，小盲與四街注額同比縮放。初始資產用 config.buyIn，跨桌保留真實資產；入桌雙方以玩家全部可用資產相同帶入。禁止另輸入 buy-in、無聲補資及偽造錢包。
- 「重設 DEMO 資產」只在未打牌／結算且非 busy 時供玩家明示操作；它重設當頁 session 與初始資產。頁面重新載入也會初始化，均非入桌無聲補資或後端持久錢包。
- JP 已正式接入原型：皇家同花順／同花順／四條為 200／50／20 倍 BET，最高一獎，預設啟用。倍率參照已核對 Hands Up；玩家正常攤牌才加獎、可用零／一／兩張底牌且不必贏底池，是本作適配。棄牌不領；NPC 不領；預覽不入帳。詳細 API 與單次入帳不變量依契約，不另寫一套獎項引擎。鬼牌、SCATTER、免費遊戲仍未做。
- NPC 分布是真正動作機率，依自己的底牌、公開牌與下注狀態計算；鎖定後只抽一次，動畫不改結果。預覽不消耗 RNG、不改牌局、不揭露下一街。別把對手動作機率叫做玩家勝率。
- 起手強化參考 Boss Duel 的弱牌條件重抽與次數上限，但只讀兩張起手分數，不看最終結果。手動底牌優先保留；雙方牌不得重複，落選候選牌回池。
- 96% 僅為對稱條件下底池 baseRtp 參考：已匹配底池返還係數 0.96，退款不納入 RTP；totalRtp 另含 JP，不能稱為 96%。4% 結算費為原型建模取捨，未確認為商業模式。積極策略舊版底池實測可超過 100%，不能隱藏或暗改牌補回目標。260,000 手歷史報表未含 JP，不當作新版總回收驗證。

## 本專案的取捨

本案只製作一款新遊戲。將各市場的熟悉體驗融入同一個核心玩法；三款舊作僅作研究及銜接目標，不拆成多款新遊戲或三套獨立模式。現行為簡化德州對戰，先前 Slot 自有牌型派彩方向不再適用。

使用者要將複雜遊戲簡單化，兼顧「先好玩」與「少量選擇能幫助銜接」。Slot POP 是體驗比喻，不是要求複製某個遊戲。社交娛樂可先由 NPC 角色反應、牌型收藏、分享成就構成；真人競技不是目標。

受眾是使用者指定的 Slot、捕魚、真人牌桌、Crash／Mini Game 市場玩家。需轉譯市場體驗時讀 [市場體驗銜接](../../../docs/03-market-bridge.md)。優先讓玩家用熟悉的操作看懂新玩法，牌型知識在遊玩中建立。不得將官方產品介紹當成整體玩家偏好或轉換效果的證據。

提出或修改一個主循環時，說清楚：

- 玩家一眼看見什麼、實際要按什麼、選擇改變什麼。
- 哪個揭曉是這一局的高潮，結果為何看得懂。
- 玩家無需背規則也能得到什麼回饋，以及自然學會哪個可轉移概念。
- 進入哪款舊作時，已理解什麼、還有哪些新規則需要介紹。

現行每街提供少量合法選擇，不增加無意義按鈕或額外貨幣／魔法。機率條用於揭曉真正的對手行動。

## 規則語意

- 若稱為德州入門，保留兩張手牌與五張共享公共牌，從七張取最佳五張；可使用零、一或兩張手牌。結算應能查看實際最佳五張；主桌目前成牌的亮邊範圍依 v6 規格，不能與完整比較牌誤混。
- 發牌階段分清三張翻牌、一張轉牌、一張河牌；顯示目前已形成的牌型，不提前洩漏未公開牌。
- 不強迫玩家記住術語；遊戲與工具採直觀英文，繁中文件可並列中英文牌型名稱。
- 同牌型可能需比點數與踢腳牌；A 可作 A2345 的低順，不能任意繞接。平手規則須按新遊戲模式另定。
- Boss Duel 的六選五、Joker、換牌、魔法，以及舊作的特殊平手處理，都不能教成標準德州。
- Hands Up 的程式 `call` 表示直接比牌；Final Table 的跟注涉及局內籌碼。跨模式導引不得只按程式變數名翻譯。

## 有意義的選擇

比較「保留／重抽」「選 A／B 手牌」「立即比牌」等候選機制時，先說明玩家能取得的資訊與可理解的理由。

若保留／重抽會改變結果分布，規格需定義牌堆及抽取方式；若使用預先生成的結果或分支，需定義各選擇實際改變哪些結果。不要用只有動畫差異的按鈕，宣稱能提升牌力或勝率。

借用 Crash 的領取／繼續前，先檢查選擇是否成立：固定手牌只增加公共牌，最佳五張的牌力不會下降。如果牌力與獎勵單調對應、沒有費用或其他失敗條件，免費再翻牌不會失去原有牌型獎勵，此時不應呈現為冒險。對手相對牌力、另起的新挑戰或不同結算規則可能形成取捨，但都要清楚定義並重新評估複雜度。

模型數據需附種子、策略、參數、樣本數與信賴區間。區分成牌頻率、贏局率、動作機率、RTP，不用其中一個代稱其他數字。比值 RTP 使用比值估計的誤差，不套用贏局率的二項誤差。

## 交付與檢查

概念討論聚焦同一款遊戲的主循環、推薦理由與代價；需要比較時，只比較具體機制的取捨。不要提前展開多款新遊戲、完整商城、活動平台或多種玩法模式。

需要驗證概念時，觀察玩家能否指出自己的手牌／公共牌、看懂最佳五張、用一句話解釋選擇，及進入目標舊作後是否較少迷惑。這些是待測指標，不是已證明的成效。

原始三個資料夾保持唯讀。研究文件與程式不同時，依目前程式記錄觀察，標明版本差異，不順手修正舊作。
